## Fallback Result Interpretation

Fallback or degraded results are expected in these places:

- `frontend/e2e/specs/full-interview-human-flow.spec.js` degraded scenario sets `fallbackResult: true`.
- `frontend/e2e/voice-real-backend.playwright.mjs` must set `fallbackResult: false`; it hits real backend HTTP/WebSocket but uses deterministic test STT/TTS providers, not external speech vendors.
- Backend/report robustness tests may intentionally trigger fallback report or low-confidence statuses.
- Voice confidence tests intentionally produce repair or confirmation paths; these are product-correct and must not be counted as interview questions.
- Real AI evals may report provider fallback, mock fallback, or degraded output depending on credentials and provider availability. Those outputs must be reported separately from pass/fail status.

- Open the analysis page and verify CV/JD review gates feel clear after a stale CV or stale JD edit.

- Run a real voice session with microphone permission and verify MP3 availability only after recording processing finishes.
- Review any real AI eval output for fallback-provider indicators before calling the result real model quality.
